# 前后端 Long 精度丢失解决方案 (Jackson Serialization)

**版本**: 2026-04-27
**所属模块**: `lin-jackson`

## 1. 为什么会有 Long 精度丢失问题？

在 Java 中，`Long` 类型的最大值是 `9223372036854775807`（19 位数字）。在现代系统中，主键经常使用**雪花算法 (Snowflake ID)** 生成，这种 ID 也是 19 位的 Long。

然而，前端浏览器中的 JavaScript 使用的是 IEEE 754 双精度浮点数来表示所有的数字（Number 类型）。JavaScript 能够安全表示的最大整数（即不丢失精度的最大值 `Number.MAX_SAFE_INTEGER`）是 `9007199254740991`（16 位数字）。

**灾难现场：**
如果后端返回一个对象：`{"id": 1234567890123456789}`
前端 JS 在解析 JSON 时，超出了安全范围，低位会被截断补零，最终前端拿到的是：`1234567890123456800`。
这时前端拿着错误的 ID 去调用后端的查询、删除接口，就会导致**找不到数据**甚至**误删数据**！

## 2. 结构构造

我们在 `lin-jackson` 这个专属模块下实现了全局序列化接管：

### 2.1 序列化定制 (`JacksonConfig.java`)
我们利用 Spring Boot 提供的 `Jackson2ObjectMapperBuilderCustomizer` 来对底层的 `ObjectMapper` 进行全局个性化定制：

```java
@Configuration
public class JacksonConfig {
    @Bean
    public Jackson2ObjectMapperBuilderCustomizer customizer() {
        return builder -> {
            // 将 Long.class (包装类) 转 String
            builder.serializerByType(Long.class, ToStringSerializer.instance);
            // 将 long.class (基本数据类型) 转 String
            builder.serializerByType(Long.TYPE, ToStringSerializer.instance);
            // 将超大数字 BigInteger 转 String
            builder.serializerByType(BigInteger.class, ToStringSerializer.instance);
        };
    }
}
```

## 3. 作用与优势

- **一劳永逸**：配置生效后，在 Controller 层返回的所有包含 `Long` 或 `long` 的字段（比如 `user.id`），都会在最终输出的 JSON 字符串中自动被套上双引号，变成 String 类型，例如 `{"id": "1234567890123456789"}`。
- **无感开发**：前端可以直接当做字符串进行安全处理，而后端在接收前端传回来的带引号的 `"id"` 字符串时，Spring 的反序列化器又会自动且正确地将其转回后端的 `Long` 类型。整个过程对业务代码**零入侵**。
