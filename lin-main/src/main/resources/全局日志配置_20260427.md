# 全局日志体系配置 (Logback)

**版本**: 2026-04-27
**所属模块**: `lin-main`

## 1. 为什么需要标准日志体系？

抛弃 `System.out.println` 是项目走向专业化的第一步：
- `System.out.println` 只有打印功能，且无法关闭。在生产环境中不仅无法持久化保存，还会严重影响性能。
- 专业的日志框架能区分级别（DEBUG, INFO, WARN, ERROR），能格式化输出时间、线程，并且最重要的是能**持久化到磁盘**。如果不存盘，服务器重启后昨天的报错记录将彻底丢失。

## 2. 结构构造

我们在 `resources` 目录下创建了 `logback-spring.xml`。这是 Spring Boot 默认且推荐的日志框架 Logback 的标准配置文件。

### 2.1 控制台输出 (`ConsoleAppender`)
开发阶段最常用的配置，负责把日志按我们设定的格式（时间、线程、级别、类名、消息）输出到 IDEA 的控制台。

### 2.2 文件归档 (`RollingFileAppender`)
这是日志持久化的核心机制：
- 它会将当前正在产生的日志写入根目录下的 `logs/application.log`。
- **滚动策略 (`TimeBasedRollingPolicy`)**：每天晚上 12 点，它会自动把昨天的 `application.log` 重命名为 `application.2026-04-26.log` 这样的格式进行归档封存，然后重新创建一个空的 `application.log` 用于今天的新记录。
- **清理策略 (`maxHistory`)**：设置了保留 30 天。它会自动删除 30 天前的旧文件，防止日志把服务器硬盘撑爆。

## 3. 作用与优势

- **有迹可循**：所有的报错、重要的业务流转信息（结合项目中各处使用的 `@Slf4j` 中的 `log.info()` 和 `log.error()`）都会被稳妥地保存在本地磁盘中。
- **日志隔离**：按天分割日志，使得排查问题时非常方便——如果今天有人反馈昨天系统出了 Bug，开发人员可以直接去下载昨天的日志文件进行分析。
- **优雅与克制**：生产环境可以通过修改全局的 `<root level="INFO">`，过滤掉繁杂的 DEBUG 信息，只保留有价值的数据。
