# Jackson 全局配置与 JSON 工具集

**版本**: 2026-04-27
**所属模块**: `lin-common-jackson`

## 1. 模块定位

随着我们引入了更多来自开源社区（如 Dromara）的优秀实践，`lin-common-jackson` 已经从单纯的“解决 Long 精度丢失”模块，升级为了**项目内所有 JSON 处理和校验的底层核心**。

## 2. 核心功能构造

### 2.1 全局序列化配置 (`JacksonConfig.java`)
我们通过定制 `Jackson2ObjectMapperBuilderCustomizer` 和引入开源配置的 `Module`，完成了以下壮举：
- **防精度丢失**：引入了自定义的 `BigNumberSerializer` 和原生的 `ToStringSerializer`，遇到超长 `Long` 或 `BigInteger` 自动转为字符串，保证前端不发生截断灾难。
- **全局时间格式化**：通过 `LocalDateTimeSerializer`，将原本繁杂的 Java 时间格式（带 `T` 等）统一收束为企业级标准的 `"yyyy-MM-dd HH:mm:ss"`。
- **自定义日期反序列化**：引入了 `CustomDateDeserializer`，结合 Hutool 强大的日期解析能力，无论前端传什么千奇百怪的时间字符串，只要逻辑合理，都能反序列化为后端的 `Date` 对象。

### 2.2 强大的 JSON 工具类 (`JsonUtils.java`)
通过依赖注入拿到 Spring 管理的 `ObjectMapper`，提供了一套极简的方法库，替代了原本散落各处的 `new ObjectMapper().writeValueAsString()`：
- `toJsonString(Object)`: 对象转字符串
- `parseObject(String, Class)`: 字符串转对象
- `parseArray(String, Class)`: 字符串转列表
- `parseMap` 和 `parseArrayMap`: 将 JSON 转为 Hutool 的增强 `Dict` 对象
- `isJson` / `isJsonObject` / `isJsonArray`: JSON 格式探针

### 2.3 声明式 JSON 格式校验 (`@JsonPattern`)
提供了一个原生的 Spring Validation 自定义注解 `@JsonPattern`。
**应用场景**：如果你的接口要求前端必须传一段 JSON 格式的字符串文本，你只需要在 DTO 的字段上打上这个注解：
```java
@NotBlank
@JsonPattern(type = JsonType.OBJECT, message = "这里必须是合法的 JSON 对象字符串")
private String configData;
```
底层的 `JsonPatternValidator` 会自动挂载 `JsonUtils.isJsonObject` 方法进行拦截校验，告别繁杂的 try-catch 判断。

## 3. 依赖项 (Dependencies)

该模块已高度内聚，除了 `spring-boot-starter-web` 以外，我们还集成了：
1. **Hutool (`hutool-core`)**：作为各类字符串、对象、集合判空的底层基座。
2. **Spring Validation (`spring-boot-starter-validation`)**：为 `@JsonPattern` 等约束注解提供引擎支持。

## 4. 优势总结

在进行企业级业务开发时，所有的 Controller 和 Service 都不需要再操心数据的输入和输出格式转换。任何有关 JSON 的处理，都应该并且只能在这个模块内收拢。
