# 限流功能 (Rate Limiter)

**版本**: 2026-04-27
**所属模块**: `lin-common-ratelimiter`

## 1. 为什么需要限流？

在高并发场景下，如果没有限流保护，系统可能面临以下问题：
- **恶意刷接口**：用户或攻击者通过脚本频繁调用接口，造成服务器资源耗尽。
- **突发流量雪崩**：某个热点接口被瞬间涌入的大量请求打垮，进而拖垮整个服务链路。
- **公平性缺失**：个别用户占用过多资源，导致其他正常用户无法得到响应。

## 2. 结构构造

我们在当前包下构建了声明式限流体系，由四个核心文件组成：

### 2.1 限流注解 (`@RateLimiter`)
通过方法注解声明限流规则，支持自定义限流 Key、限流次数、时间窗口、限流类型等参数。内置 SpEL 表达式支持，可动态获取方法参数作为限流 Key。

```java
@RateLimiter(key = "#userId", count = 5, time = 60, limitType = LimitType.IP)
@GetMapping("/api/user/{userId}")
public Result<User> getUser(@PathVariable String userId) { ... }
```

### 2.2 限流类型枚举 (`LimitType.java`)
提供三种限流策略：
- **DEFAULT** — 全局限流，所有请求共享同一计数器
- **IP** — 按请求 IP 地址限流，每个 IP 独立计数
- **CLUSTER** — 按集群实例限流，每个后端服务实例独立计数

### 2.3 限流切面 (`RateLimiterAspect.java`)
基于 Spring AOP 的 `@Before` 通知，在方法执行前通过 Redisson 的 `RRateLimiter` 进行令牌校验。超限时抛出 `BusinessException`，由全局异常处理器统一格式化返回。

### 2.4 自动配置 (`RateLimiterConfig.java`)
通过 `@AutoConfiguration` + `@ConditionalOnBean(RedissonClient.class)` 实现条件注入。仅当项目中存在可用的 `RedissonClient` Bean（即配置了 Redis 连接）时，限流模块才自动激活。

## 3. 依赖项 (Dependencies)

| 依赖 | 用途 |
|------|------|
| `lin-common-core` | 复用 `BusinessException` 异常类 |
| `spring-boot-starter-aop` | 提供切面支持 |
| `redisson-spring-boot-starter` (3.40.0) | 基于 Redis 的分布式限流实现 |

## 4. 优势总结

- **声明式使用**：一行注解即可完成限流配置，零侵入业务代码。
- **分布式支持**：基于 Redis + Redisson，天然支持多实例部署场景下的统一限流。
- **灵活 Key 策略**：支持 SpEL 动态表达式，可按用户、IP、接口等任意维度组合限流。
- **自动激活**：有条件 Bean 注入机制，无需限流时只需不配置 Redis 即可零成本移除。
