# 响应加密模块 (lin-common-crypto)

**版本**: 2026-05-01
**所属模块**: `lin-common-crypto`

## 1. 为什么需要响应加密？

TLS 是传输层安全，保护数据在网络链路上的机密性。但以下场景 TLS 会被绕过或降级：

- **企业代理/网关**：公司网络中间人代理，能读取 HTTPS 明文内容
- **浏览器扩展**：恶意扩展可读取 DOM 中的接口响应数据
- **网络日志**：开发者工具、抓包工具的网络日志记录明文响应
- **合规要求**：某些行业（金融、医疗）要求应用层加密（defense in depth）

本模块在应用层对 `Result<T>` 的 `data` 字段做 **AES-256-GCM 透明加密**，即使 TLS 被绕过，拦截者拿到的也是密文。

## 2. 设计原则

- **透明加密** — Controller 代码零感知，加 `@EncryptResponse` 注解即可，无需修改业务逻辑
- **算法安全** — AES-256-GCM 认证加密，同时提供机密性和完整性（防篡改）
- **密钥隔离** — 每个会话独立随机密钥，一个会话被破解不影响其他会话
- **关注点分离** — 加密密钥与 JWT 认证密钥独立，各自有独立的生命周期
- **零额外依赖** — AES-GCM 在 Java 21 `javax.crypto` 中内置，无需引入第三方加密库

## 3. 模块结构

```
lin-common-crypto/
└── src/main/java/com/lin/crypto/
    ├── annotation/
    │   └── EncryptResponse.java           # @EncryptResponse 注解（类/方法）
    ├── advice/
    │   └── EncryptResponseBodyAdvice.java # ResponseBodyAdvice，JSON 序列化前加密 data 字段
    ├── core/
    │   ├── CryptoService.java             # AES-256-GCM 加解密核心（纯静态工具）
    │   ├── SessionKeyProvider.java        # 会话密钥管理接口
    │   └── UserIdProvider.java            # 当前用户ID提供者接口（解耦安全模块）

        └── CryptoAutoConfiguration.java   # 自动装配（@AutoConfiguration）
```

## 4. 架构设计 — 两层密钥 + 三层加密

### 4.1 密钥体系

```
┌────────────────────────────────────────────────────┐
│                    JWT 令牌（认证）                   │
│  作用：验证"你是谁"                                  │
│  密钥：lin.security.token.secret（HMAC-SHA256）      │
│  生命周期：全局固定                                   │
└────────────────────┬───────────────────────────────┘
                     │ 正交独立
┌────────────────────▼───────────────────────────────┐
│                会话密钥（加密）                       │
│  作用：保护"你看到什么"                               │
│  密钥：AES-256 随机生成，每次登录不同                   │
│  生命周期：会话级，7200秒过期                          │
└────────────────────────────────────────────────────┘
```

两个密钥在密码学上完全独立——JWT 密钥泄露不会导致历史加密数据被解密，反之亦然。

### 4.2 完整数据流

```
┌─────────────────────────────────────────────────────────────────┐
│                        1. 登录阶段                                │
│                                                                 │
│  POST /auth/login                                               │
│    │                                                            │
│    ├─ 服务端生成两个凭证：                                        │
│    │   ├─ JWT token (HMAC-SHA256 签名)   → 认证                 │
│    │   └─ AES-256 会话密钥 (随机)        → 加密                  │
│    │                                                            │
│    ├─ 服务端存储: userId → SecretKey (ConcurrentHashMap)         │
│    │                                                            │
│    └─ 响应: { "token": "jwt...", "encryptKey": "<base64-key>" } │
│                                                                 │
│  前端: encryptKey 存闭包变量（不放 localStorage/全局）             │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                     2. 加密响应阶段                               │
│                                                                 │
│  GET /auth/info (带 Authorization: Bearer <jwt>)                │
│    │                                                            │
│    ├─ TokenAuthenticationFilter → 解析 JWT → UserContext.set()  │
│    │                                                            │
│    ├─ SecurityInterceptor → 验证认证 → 放行                      │
│    │                                                            │
│    ├─ Controller → return Result.success(data)                  │
│    │                                                            │
│    ├─ EncryptResponseBodyAdvice.beforeBodyWrite():              │
│    │   ├─ 检查 @EncryptResponse 注解（方法 > 类）                 │
│    │   ├─ UserIdProvider → 获取当前 userId                       │
│    │   ├─ SessionKeyProvider → 获取会话密钥                       │
│    │   ├─ Jackson 序列化 data 对象 → JSON bytes                  │
│    │   ├─ CryptoService.encrypt(jsonBytes, key)                 │
│    │   │   ├─ 生成 12 字节随机 IV                                │
│    │   │   ├─ AES-256-GCM 加密                                   │
│    │   │   └─ 输出: base64( IV[12] || ciphertext || tag[16] )   │
│    │   ├─ result.data = base64String                            │
│    │   └─ 响应头 X-Encrypted: true                               │
│    │                                                            │
│    └─ JSON 序列化 → 写出响应                                     │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                     3. 前端解密阶段                               │
│                                                                 │
│  const resp = await fetch('/auth/info', {                       │
│    headers: { Authorization: `Bearer ${token}` }                │
│  });                                                            │
│                                                                 │
│  if (resp.headers.get('X-Encrypted')) {                         │
│    const raw = Uint8Array.from(atob(result.data), ...);         │
│    const iv = raw.slice(0, 12);                                 │
│    const ct = raw.slice(12);                                    │
│    const plain = await crypto.subtle.decrypt(                   │
│      { name: 'AES-GCM', iv }, sessionKey, ct                    │
│    );                                                           │
│    result.data = JSON.parse(new TextDecoder().decode(plain));   │
│  }                                                              │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 加密输出格式

```
原始 data 对象 → Jackson 序列化 → JSON bytes → AES-256-GCM 加密

输出: base64( IV[12 bytes] || ciphertext[...] || GCM tag[16 bytes] )
                        │              │               │
                        │              │               └─ 认证标签（防篡改）
                        │              └─ 密文
                        └─ 随机初始化向量（每次加密不同，无需保密）
```

GCM 的 16 字节认证标签已由 `Cipher.doFinal()` 自动拼接在密文末尾，解密时会自动校验——如果密文被篡改，解密直接抛 `AEADBadTagException`。

## 5. 快速开始

### 5.1 引入依赖

```xml
<dependency>
    <groupId>com.lin</groupId>
    <artifactId>lin-common-crypto</artifactId>
</dependency>
```

### 5.2 配置文件

```yaml
lin:
  crypto:
    enabled: true                 # 是否启用加密模块，默认 true
    session:
      ttl-seconds: 7200           # 会话密钥过期时间（秒），默认 7200
      cleanup-interval-seconds: 300 # 过期会话清理间隔（秒），默认 300
```

### 5.3 使用注解

```java
// 整个 Controller 加密
@EncryptResponse
@RestController
@RequestMapping("/api/sensitive")
public class SensitiveController {

    @GetMapping("/data")
    public Result<Data> getData() { ... }  // 自动加密
}

// 单个方法加密
@RestController
public class UserController {

    @EncryptResponse
    @GetMapping("/profile")
    public Result<UserProfile> profile() { ... }  // 仅此方法加密
}
```

### 5.4 登录时返回加密密钥

```java
@Anonymous
@PostMapping("/login")
public Result<Map<String, String>> login(@RequestBody LoginRequest request) {
    LoginUser user = new LoginUser();
    user.setUserId(UUID.randomUUID().toString());
    // ...

    String token = tokenProvider.createToken(user);
    String encryptKey = sessionKeyProvider.createSession(user.getUserId());
    return Result.success(Map.of("token", token, "encryptKey", encryptKey));
}
```

## 6. 注解说明

### `@EncryptResponse` — 响应加密

标记类或方法的响应 `data` 字段需要 AES-256-GCM 加密。

| 位置 | 效果 |
|------|------|
| 类上 | 整个 Controller 所有方法加密 |
| 方法上 | 仅该方法加密 |
| 无注解 | 不加密，原样返回 |

**前提条件**：当前请求必须已认证（`UserContext` 中有 userId），且该用户登录时已创建会话密钥。匿名接口即使加了 `@EncryptResponse` 也会跳过加密（warn 日志）。

## 7. 核心组件

### 7.1 CryptoService — 加解密核心

纯静态工具类，不依赖 Spring 上下文，可直接在任何 Java 项目中独立使用。

| 方法 | 说明 |
|------|------|
| `generateKey()` | 生成随机 AES-256 密钥 |
| `encrypt(byte[], SecretKey)` | AES-256-GCM 加密，返回 base64 字符串 |
| `decrypt(String, SecretKey)` | 解密 base64 字符串，返回原始字节 |

**安全参数**：
| 参数 | 值 | 说明 |
|------|-----|------|
| 加密算法 | AES/GCM/NoPadding | 认证加密 |
| 密钥长度 | 256 bit | AES-256 |
| IV 长度 | 12 字节 | GCM 推荐值 |
| GCM 标签长度 | 128 bit | 标准认证强度 |
| 随机源 | `SecureRandom.getInstanceStrong()` | 操作系统熵源 |

### 7.2 SessionKeyProvider — 会话密钥管理

```java
public interface SessionKeyProvider {
    String createSession(String userId);   // 生成密钥，返回 base64 编码（给前端）
    SecretKey getKey(String userId);       // 获取密钥（服务端加密用）
    void removeSession(String userId);     // 登出时移除
}
```

### 7.3 InMemorySessionKeyProvider — 默认实现

- **存储**: `ConcurrentHashMap<String, CacheEntry>` — userId → (SecretKey, createdAt)
- **过期**: 读取时惰性检查 TTL；后台定时线程每 300 秒批量清理
- **线程安全**: ConcurrentHashMap 保证并发读写安全
- **Daemon 线程**: 清理线程为 daemon，不阻止 JVM 退出

### 7.4 UserIdProvider — 用户识别（解耦设计）

```java
@FunctionalInterface
public interface UserIdProvider {
    String getCurrentUserId();
}
```

**为什么用接口而非直接依赖 `UserContext`？**

`lin-common-crypto` 是基础设施层，不应反向依赖 `lin-common-security`（安全层）。`UserIdProvider` 通过接口抽象了这一依赖：

- `CryptoAutoConfiguration` 中通过反射创建默认实现 → `Class.forName("com.lin.security.context.UserContext").getMethod("getUserId").invoke(null)`
- 当 `lin-common-security` 模块不存在时，`@ConditionalOnClass` 检测失败，Bean 不创建
- 外部项目可注入自定义 `UserIdProvider` Bean 覆盖默认行为

这保持了模块的独立性——crypto 模块可脱离 security 模块独立使用。

### 7.5 EncryptResponseBodyAdvice — 透明加密切面

实现 `ResponseBodyAdvice<Object>`，在 Jackson 序列化之前拦截响应：

```
Controller 返回 Result<T>
  → supports() 检查 @EncryptResponse 注解
    → 无注解 → 跳过
    → 有注解 → beforeBodyWrite() 执行加密
      → 检查 Result.data 非 null
      → 获取 userId → 获取 sessionKey
      → Jackson 序列化 data → JSON bytes
      → CryptoService.encrypt()
      → 替换 data 为 base64 密文字符串
      → 设置 X-Encrypted: true 响应头
```

**异常处理**：加密过程中任何异常都不会中断响应——捕获异常、记录 error 日志、返回原始 body（降级策略）。

## 8. 配置参考

```yaml
lin:
  crypto:
    # 是否启用加密模块，默认 true
    # 设为 false 后所有 @EncryptResponse 注解失效
    enabled: true

    # 会话密钥管理
    session:
      # 会话密钥过期时间，单位秒，默认 7200（2小时，与 JWT 过期一致）
      ttl-seconds: 7200
      # 过期会话后台清理间隔，单位秒，默认 300（5分钟）
      cleanup-interval-seconds: 300
```

## 9. 与其他模块的协作

```
lin-module-admin (AuthController)
  ├─ lin-common-security → JWT 认证 + UserContext
  └─ lin-common-crypto   → SessionKeyProvider + @EncryptResponse
       │
       ├─ 登录: 调用 sessionKeyProvider.createSession(userId)
       │        返回 encryptKey 给前端
       │
       └─ 响应: @EncryptResponse 触发 EncryptResponseBodyAdvice
                通过反射调用 UserContext.getUserId()
                查找会话密钥 → 加密 data 字段
```

**不依赖安全模块的原因**（第 7.4 节）是通过反射桥接实现的，避免模块间的硬耦合。

## 10. 安全考量

| 考量 | 方案 |
|------|------|
| 密钥传输 | 仅在登录响应中返回一次（HTTPS 保护），后续不再传输 |
| 密钥存储（服务端） | `ConcurrentHashMap` 内存存储，不持久化，不写日志 |
| 密钥存储（前端） | JavaScript 闭包变量，不放 `localStorage`/`window`，页面刷新即销毁 |
| 每次加密唯一性 | 每响应生成新 12 字节随机 IV，即使同一数据多次加密，输出也不同 |
| 防篡改 | GCM 认证标签，篡改密文 → `AEADBadTagException` |
| 重放攻击 | 应用层不防重放（属于会话层问题，由 HTTPS + JWT 时效性保证） |
| 密钥轮换 | 重新登录即获得新密钥，旧密钥 TTL 过期后自动清理 |
| 匿名接口 | 即使标注 `@EncryptResponse` 也无密钥可用，跳过加密并 warn 日志 |

## 11. 禁用加密模块

```yaml
lin:
  crypto:
    enabled: false
```

设为 `false` 后，`CryptoAutoConfiguration` 跳过所有 Bean 注册，`@EncryptResponse` 注解无效果。

## 13. 拷贝到其他项目

模块仅依赖 `lin-common-core` 和 Java 21 标准库：

### 1. 拷贝源码

```
target-project/
└── common/
    ├── lin-common-core/    ← 复制（如果还没有）
    └── lin-common-crypto/  ← 复制
```

### 2. 如果没有 `lin-common-security`（或等价模块）

提供自定义 `UserIdProvider` Bean 即可，无需引入安全模块：

```java
@Bean
public UserIdProvider userIdProvider() {
    // 从你的认证体系获取当前用户 ID
    return () -> YourAuthContext.getCurrentUserId();
}
```

这样 `SessionKeyProvider` 就能正常查找密钥。没有自定义 `UserIdProvider` 时，默认实现返回 `null`，所有 `@EncryptResponse` 接口静默跳过加密。

### 3. 如果响应格式不同

项目不使用 `Result<T>` 时，修改 `EncryptResponseBodyAdvice.beforeBodyWrite()` 中的类型判断和 setter 调用即可，核心加解密逻辑（`CryptoService`）无需修改。
