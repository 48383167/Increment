# Redis 模块 (lin-common-redis)

**版本**: 2026-04-27
**所属模块**: `lin-common-redis`

## 1. 为什么需要 Redis 模块？

在 Spring Boot 项目中直接使用 `redisson-spring-boot-starter` 会面临以下问题：
- **序列化不统一**：默认使用 Redisson 自带的编解码器，与项目 Jackson 配置不一致，导致日期格式、大数字处理等行为不一致。
- **Key 管理混乱**：多个模块各自维护 Redis Key，容易出现 Key 冲突或难以追踪的问题。
- **配置分散**：Redisson 的连接池、线程等参数分散在 `application.yml` 各处，缺少统一管理。
- **工具缺失**：没有封装的 `RedisUtils`，每次操作都要手动获取 `RedissonClient`。

本模块在 Redisson 之上做了一层封装，统一序列化、Key 前缀、配置管理，并提供了开箱即用的 `RedisUtils`。

## 2. 结构构造

### 2.1 自动配置 (`RedisConfig.java`)

通过 `@AutoConfiguration` 自动激活。核心行为：

- **统一序列化**：使用 `CompositeCodec`（StringCodec 处理 Key + TypedJsonJacksonCodec 处理 Value），确保存入 Redis 的数据与项目 Jackson 配置一致（日期 `yyyy-MM-dd HH:mm:ss`、大数字转字符串等）。
- **全局 Key 前缀**：通过 `KeyPrefixHandler` 实现 `NameMapper`，所有 Key 自动加上 `redisson.key-prefix` 前缀。例如 `key-prefix: lin` 时，`myKey` 实际存储为 `lin:myKey`。
- **线程池调优**：支持配置 Redisson 工作线程数和 Netty 线程数。
- **连接池管理**：单节点和集群两种模式，可分别配置超时时间、连接池大小、最小空闲连接数等。
- **Lua 脚本缓存**：开启 `useScriptCache`，减少网络传输。

### 2.2 配置属性 (`RedissonProperties.java`)

`@ConfigurationProperties(prefix = "redisson")` 绑定：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `key-prefix` | String | Redis Key 全局前缀 |
| `threads` | Integer | Redisson 工作线程数 |
| `netty-threads` | Integer | Netty 线程数 |
| `single-server-config` | 内嵌对象 | 单节点连接池参数 |
| `cluster-servers-config` | 内嵌对象 | 集群连接池参数 |

### 2.3 Key 前缀处理器 (`KeyPrefixHandler.java`)

实现 Redisson 的 `NameMapper` 接口：
- `map(name)` → 写入 Redis 前自动加前缀
- `unmap(name)` → 读取 Redis 后自动去前缀

### 2.4 Redis 工具类 (`RedisUtils.java`)

静态工具类，封装常用操作：

| 分类 | 方法 |
|------|------|
| **通用** | `setCacheObject`, `getCacheObject`, `deleteObject`, `isExistsObject`, `expire`, `getTimeToLive` |
| **扫描** | `keys` (按 pattern 扫描), `deleteKeys` (按 pattern 批量删除) |
| **List** | `setCacheList`, `getCacheList`, `addCacheList` |
| **Set** | `setCacheSet`, `getCacheSet`, `addCacheSet` |
| **Map** | `setCacheMap`, `getCacheMap`, `setCacheMapValue`, `getCacheMapValue`, `delCacheMapValue` |
| **原子** | `setAtomicValue`, `getAtomicValue`, `incrAtomicValue`, `decrAtomicValue` |
| **限流** | `rateLimiter(key, rateType, count, time, timeout)`, `getClientId()` |

> 限流方法供 `lin-common-ratelimiter` 模块调用，实现分布式限流。

### 2.5 客户端注入器 (`RedisClientInitializer.java`)

启动时自动将 Spring 容器中的 `RedissonClient` 注入到 `RedisUtils` 静态字段中。仅当容器中存在 `RedissonClient` Bean 时才激活。

## 3. 依赖项 (Dependencies)

| 依赖 | 用途 |
|------|------|

## 4. 配置示例

### 4.1 单节点模式（默认）

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      password: 123456
      database: 0
      timeout: 10s

redisson:
  key-prefix: lin
  threads: 16
  netty-threads: 16
  single-server-config:
    client-name: ${spring.application.name}
    connection-minimum-idle-size: 8
    connection-pool-size: 32
    idle-connection-timeout: 10000
    timeout: 3000
    subscription-connection-pool-size: 50
```

### 4.2 集群模式

```yaml
spring:
  data:
    redis:
      cluster:
        nodes:
          - 192.168.1.1:6379
          - 192.168.1.2:6379
          - 192.168.1.3:6379
      password: 123456

redisson:
  key-prefix: lin
  cluster-servers-config:
    master-connection-pool-size: 32
    slave-connection-pool-size: 32
    master-connection-minimum-idle-size: 8
    slave-connection-minimum-idle-size: 8
```

## 5. 与限流模块的协作

`lin-common-ratelimiter` 通过 `optional` 方式依赖本模块：

```
lin-common-ratelimiter ──(optional)──> lin-common-redis ──> redisson ──> Redis
```

- 当项目同时引入两个模块时，`RateLimiterConfig` 检测到 `RedisUtils` 类存在，自动激活限流切面。
- 当只引入 `lin-common-ratelimiter` 而不引入 `lin-common-redis` 时，限流模块不会激活，不影响项目启动。
- 这种设计保证了双方可以独立演进，也可以方便地替换底层实现。

## 6. 优势总结

- **序列化一致性**：存入 Redis 的数据与接口返回的 JSON 格式一致，避免日期格式、大数字精度等差异。
- **全局 Key 前缀**：避免多模块 Key 冲突，支持同 Redis 实例多项目共享。
- **开箱即用**：引入依赖、配置连接即可使用 `RedisUtils`，无需手动创建 Client。
- **可剥离设计**：限流模块通过 optional 依赖实现松耦合，需要时激活，不需要时零成本移除。
